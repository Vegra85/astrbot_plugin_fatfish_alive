# 鱼力max · 活人感

> **鱼力max 系列（鱼有分寸）**：[活人感](https://github.com/Vegra85/astrbot_plugin_fatfish_alive) · [认 AI](https://github.com/Vegra85/astrbot_plugin_fatfish_aiguard) · [看图懂梗](https://github.com/Vegra85/astrbot_plugin_fatfish_seememe) · [法庭](https://github.com/Vegra85/astrbot_plugin_fatfish_court) —— 每个都能单独用，一起装自动让路。作者 Vegra85；跟市场上其他叫「大肥鱼」的插件无关（11-08 起由「大肥鱼 · X」改叫「鱼力max · X」，仓库名和配置都没变）。

AstrBot 插件。让机器人在 QQ 里像个真人：不一条一条机械地回、不是人人说话都接、别人之间说话不插嘴、花得多了就少说点、出了岔子也不会把报错发到群里；对方撤回了、说了「算了」，还没发的就不发了；想的话还能像真人一样一段一段打字、对方又说话了就不往下说。

v0.5.0 新加（新手好用的四样）：**档位**（配置最上面一项：安静 / 默认 / 话多 / 自定义，新手只调这一项）、**哪里不对 → 改哪项**（下面一节 + 面板标签页）、**启动自检**（AstrBot 自己的设置里跟活人感打架的，日志 / 面板 / `/活人感 自检` 都能看；只读）、**免打扰时段**（默认不开）。

v0.4.0 新加：**撤回 / 算了**（默认开）和 **接话打分**（借 Inner Thoughts 论文的 8 条理由，默认只记录不改行为，面板上看每次接不接、为什么）。

由原来三个插件合并而成，再加兜底和发消息两块：

| 模块 | 干什么 | 原来的插件 |
|---|---|---|
| 攒一攒 | 同一个人连着发好几条：等他停下来，并成一件事只回一次（图也带上）；说了「稍等 / 我还没说完」就多等一阵；最后一句的尾巴含糊（「然后」「那个」、逗号、省略号）先问一下判断模型他说完没有；私聊里他还在「正在输入」就再等等（v0.3.0）；还排着没回、他撤回了 → 那条不回（v0.4.0） | astrbot_plugin_fatfish_gather |
| 群聊节奏 | 没 @ 但在接它的话也接（别人之间在说话、开头叫的是别人的，不当成在跟它说）；说上话以后在线聊一阵、挑着接；冷场试探一句；到点说句收尾话再潜水；「好了 / 就这样 / 睡了」不接；接话打分（8 条理由，v0.4.0，默认影子） | astrbot_plugin_fatfish_rhythm |
| 省 token | 把最近 24 小时花的钱算成「回复意愿」，花得越多越不爱回；私聊照回、被 @ 几乎都回，没人找它时省得最多；管理员可以「火力全开」 | astrbot_plugin_fatfish_budget |
| 兜底 | 框架报错不发到聊天里；模型空回 / 只有 `<think>` 就补调一次；回复开头漏出来模型的英文草稿（「Question: … Answer: …」）去掉（v0.4.1）；可选去掉「作为一个AI」「希望对你有帮助」这类客服腔；群友手打的「[群聊节奏]」标成他打的字，防伪造（v0.3.0） | — |
| 发消息（v0.2.0） | 群里只引用「找她的那一条」，私聊、一来一回不挂引用；分段发到一半他撤回了 / 说「算了」→ 剩下的不发（v0.4.0，默认开）；可选打字节奏（每段按字数慢慢发）和打字刹车（分段发到一半对方又说话了，后面的不发了） | — |

一个面板看全部（总览 + 五个标签页：攒一攒 / 群聊节奏 / 省 token / 自检 / 哪里不对），一份配置（按模块分组，最上面是档位）。

## 安装

- **插件市场**：WebUI → 插件 → 插件市场，搜「鱼力max」或「活人感」。
- **从链接安装**：WebUI → 插件 → 安装 → 从链接安装，填 `https://github.com/Vegra85/astrbot_plugin_fatfish_alive`。
- **从文件安装**：WebUI → 插件 → 安装 → 从文件安装，选这个仓库的 zip。

要求：AstrBot ≥ 4.29（在 4.29.3、4.29.4 上测过）；QQ（aiocqhttp / NapCat）。

## 新手先看：档位（v0.5.0）

配置最上面一项「档位」：**安静 / 默认 / 话多 / 自定义**。新手只调这一项就行。

- 选安静 / 默认 / 话多：下面这 12 项按档位走，配置里你填的不看（配置里这几项的说明后面标着「档位管」，提示里写着每档是多少）。
- 选「自定义」：全按各分组里的细项，跟以前一样一项项调。
- 默认是「默认」档，数跟 v0.4.3 的默认值一模一样。**升级的人**：你以前改过这 12 项里的哪一项，第一次加载 v0.5.0 时自动把档位设成「自定义」（日志里写一笔），行为不变。
- 面板总览「档位盖住的几项」：现在按档位走的是哪几项、多少（你填的那个数划掉显示）。

| 配置项 | 键 | 安静 | 默认 | 话多 | 为什么这么定 |
|---|---|---|---|---|---|
| 接话：多少分直接接 | `rhythm.yes_score` | 5 | 4 | 3 | 安静：要「它刚回的就是他 + 说「你」+ 在问 + 紧跟着」这种很明显的才直接接；话多：它刚回的人紧跟着说一句就接 |
| 接话：多少分以下直接不接 | `rhythm.no_score` | 2.5 | 1.5 | 1 | 两条线中间的交给模型看一眼：安静少问（也少花判断的钱），话多多问 |
| 接话：同一个人不 @ 最多连着接几轮 | `rhythm.max_turns` | 3 | 5 | 8 | 同一个人不 @ 连着聊几轮就停下等 @：安静 3 轮，话多 8 轮（防两个机器人对聊的上限一直都在） |
| 在线一阵：没点名的消息挑着接的概率 | `rhythm.reply_prob` | 0.1 | 0.3 | 0.5 | 最直接决定插嘴多不多：在线时没点名的话，十句挑一句 / 三句 / 五句 |
| 在线一阵：每次在线最多挑着接几次 | `rhythm.max_replies` | 2 | 6 | 10 | 一次在线里自己插嘴的上限 |
| 在线一阵：每次在线最少几分钟 | `rhythm.online_min` | 4 | 8 | 12 | 说上话以后跟着聊多久：在线越久，插嘴的机会越多 |
| 在线一阵：每次在线最多几分钟 | `rhythm.online_max` | 8 | 15 | 20 | 同上（在线时长在最少和最多之间随机） |
| 冷场：试探一句的概率 | `rhythm.probe_prob` | 0 | 0.3 | 0.5 | 安静的人冷场了不会主动找话；话多的一半时候会顺着话题再说一句 |
| 每个群每小时最多主动说几句 | `rhythm.lines_per_hour` | 1 | 4 | 6 | 冷场试探 + 收尾话，每个群每小时的总上限 |
| 花到多少美元 意愿掉到一半左右 | `budget.half_usd` | 0.25 | 0.45 | 0.9 | 安静也更省：花到 $0.25 意愿就掉一半；话多到 $0.9 才掉一半（只影响它自己想插嘴的那些，有人找它照回） |
| 意愿的底线 | `budget.floor` | 0.05 | 0.1 | 0.2 | 花得再多也留着的意愿 |
| 基础等几秒 | `gather.base_sec` | 3 | 2 | 1.5 | 安静的人回得慢一点、更愿意等你说完；话多的回得快 |

档位管的是「它自己想不想开口」和「回得快不快」。有人 @ / 引用 / 用唤醒词叫它、私聊，三个档位都照回（省 token 的「有人找它就一定回」照旧），只是安静档等他说完会多等一秒。

## 哪里不对 → 改哪项（v0.5.0）

面板也有这张表（「哪里不对」标签页，跟这里是同一份）。「改哪项」写的是配置里那一项的中文名，后面是键名；标着「档位管」的项要先把档位选成「自定义」才改得动。AstrBot 自己的设置写的是它在 AstrBot 配置里的位置（这几项启动自检也会查）。

| 哪里不对 | 先看什么 | 改哪项 |
|---|---|---|
| 群里太吵 / 插嘴太多 | 面板「群聊节奏」：今天接话、挑着接各几次，「最近的接话判断」里接的都是什么；面板「自检」：AstrBot 自带的「主动回复」开没开 | 「档位（新手只调这一项）」`alive.preset`：改成「安静」<br>「在线一阵：没点名的消息挑着接的概率」`rhythm.reply_prob`：还嫌多：先把「档位」改成「自定义」，再把这项调低（比如 0.1）<br>「接话：多少分直接接」`rhythm.yes_score`：先把「档位」改成「自定义」，再调高（比如 5），没 @ 时要更明显才接<br>「在线一阵：说上话以后跟着聊一阵」`rhythm.rhythm_enable`：不想要「说上话以后跟着聊一阵」就关掉<br>AstrBot 配置 → 扩展功能 → 群聊上下文感知 →「主动回复」：开着就关掉（它跟群聊节奏抢着回） |
| 群里太安静 / 没 @ 就不说话 | 面板总览：群聊节奏是不是在让路（装了同类插件）、现在是不是在免打扰；面板「群聊节奏」：最近的接话判断是不是都「分不够」 | 「档位（新手只调这一项）」`alive.preset`：改成「话多」<br>「开启群聊节奏」`rhythm.enable`：确认开着<br>「只在这些群里用」`rhythm.groups`：填了群号的话，确认这个群在里面<br>「接话：多少分直接接」`rhythm.yes_score`：先把「档位」改成「自定义」，再调低（比如 3）<br>「免打扰时段」`alive.quiet_hours`：看现在是不是在免打扰时段 |
| 回得太慢 | 面板「攒一攒」：最近几次合并「等了几秒」；日志里的 [攒一攒]（尾巴含糊问了模型、他还在输入） | 「基础等几秒」`gather.base_sec`：先把「档位」改成「自定义」，再调小（或者直接换「话多」档：1.5 秒）<br>「尾巴含糊：多看一眼再回（v0.3.0）」`gather.tail_vague`：嫌「尾巴含糊多看一眼」慢就关掉<br>「私聊里他还在输入：多等一会儿（v0.3.0）」`gather.typing_wait`：私聊里嫌等他打完字慢就关掉<br>「打字节奏（默认关）」`send.typing_human`：开着打字节奏的话，关掉或者调高下一项<br>「打字节奏：每秒打几个字」`send.typing_cps`：调高 |
| 连着发几条，它一条一条回 | 面板总览：攒一攒是不是在工作、是不是在让路（装了消息防抖类插件）。一句回话分成几段发出来不是这个问题，那是 AstrBot 的「分段回复」 | 「开启攒一攒再回」`gather.enable`：确认开着<br>「私聊里攒」`gather.private`：私聊连发的：确认开着<br>「群里攒」`gather.group`：群里连发的：确认开着<br>「这些群不攒」`gather.skip_groups`：这个群不能在里面<br>「强制开攒一攒（不让路）」`compat.force_gather`：在让路、又想用攒一攒就打开（或者关掉那个插件的防抖） |
| 被 @ 了不回 | 日志里那条后面有没有 [省token]「这次不回」、[兜底]、免打扰；面板「省 token」→ 最近的决定；面板「自检」 | 「有人找它就一定回（不掷骰子）」`budget.never_skip_sought`：确认开着（有人找它就一定回）<br>「免打扰时被 @ 也不回（默认关）」`alive.quiet_at_too`：免打扰时也想回 @ 就关掉<br>AstrBot 配置 → AI → 其他配置 →「额外唤醒前缀」：填了就清空（消息开头没这个前缀，AstrBot 不叫模型） |

| 跟别的机器人聊个没完 | 面板「群聊节奏」→ 各个群：「连着接了几轮」 | 「接话：同一个人不 @ 最多连着接几轮」`rhythm.max_turns`：先把「档位」改成「自定义」，再调小（或者直接换「安静」档：3 轮）<br>「别人家的 AI 不接话、不挑着接」`rhythm.skip_ai`：打开，再装「鱼力max · 认 AI」（它认出来的别家 AI 不接话） |

| 话说到一半停了 / 后面几段没发 | 日志里的 [刹车]、[叫停]：写着因为什么停的 | 「撤回 / 算了：剩下的不发（v0.4.0）」`send.halt`：不想他一说「算了」就停，关掉<br>「打字刹车（默认关）」`send.typing_brake`：关掉打字刹车（默认就是关的） |

## 启动自检（v0.5.0）

插件加载时（热重载也算）查一遍 AstrBot 自己的设置里会跟活人感打架的，写进日志（一条一行：现在怎样、为什么、在哪改）和面板「自检」标签页；QQ 里管理员发 `/活人感 自检`、面板点「重新检查」也会重新查。**只读**：只告诉你改哪里，不替你改 AstrBot 的配置。AstrBot 有几份配置文件的，每份都查、写明是哪份。

| 等级 | 查什么 | 为什么打架 | 在哪改（AstrBot 配置 → …） |
|---|---|---|---|
| 冲突 | 「主动回复」开着（回复概率大于 0） | 没 @ 的群消息它按概率直接叫模型，跟群聊节奏是两套在抢着回：群聊节奏判断不该接的它照样回，两边都接时一句话回两遍 | 扩展功能 → 群聊上下文感知 →「主动回复」 |
| 冲突 | 「流式输出」开着（QQ 不支持流式，默认「实时分段回复」） | 边生成边发、不经过「发送前」那一步：兜底拦不到报错和草稿，群聊节奏的 [[不说]] 会原样发出去，发消息模块（引用 / 打字节奏 / 刹车 / 叫停）管不到 | AI → 其他配置 →「流式输出」（或者「不支持流式回复的平台」选关闭流式） |
| 冲突 | 「隔离对话」开着 | 群里一人一个会话：引用、打字刹车、冷场试探 / 收尾记进对话记录，都是按「一个群一个会话」算的，会失灵 | 平台与消息 → 基本 →「隔离对话」 |
| 冲突 | 「唤醒词」里有一项是空的 | 每句话都算在叫它：群里每条都叫模型、都回 | 平台与消息 → 基本 →「唤醒词」 |
| 冲突 | 「额外唤醒前缀」填了 | 开头没这个前缀 AstrBot 不叫模型：群聊节奏决定接的那句不会回（填的就是唤醒词「/」的不算，AstrBot 会自己去掉） | AI → 其他配置 →「额外唤醒前缀」 |
| 建议 | 「是否忽略 @ 全体成员事件」没开 | 群公告 @全体成员，它也跟着回一句（省 token 当成有人找它、一定回） | 平台与消息 → 其他配置 |
| 建议 | 群聊上下文一次最多带 200 条以上 | 群一热闹，一次就是几千上万个 token：花钱快、模型也容易被带偏 | 扩展功能 → 群聊上下文感知 →「注入上下文最大消息数量」改成 50～100 |
| 建议 | 「群聊消息记录注入上下文」没开 | 接话 / 挑着接时，模型看不到群里前面在聊什么 | 扩展功能 → 群聊上下文感知 |
| 建议 | 「回复时 @ 发送人」开着 | 它自己挑着接的那几句也 @ 人，像在点名 | 平台与消息 → 基本 |
| 建议 | AstrBot 的「引用回复」开着，活人感的「群里引用哪条」选了「不管」/ 发消息关了 | 攒一攒并了几条时，引用挂在最后补的那句；私聊、一来一回也挂引用 | 活人感配置 → 发消息 |
| 建议 | 开了打字节奏 / 打字刹车，AstrBot 的「分段回复」没开 | 整段回话就是一条，刹车没得刹 | 扩展功能 → 分段回复 |
| 建议 | 开了打字节奏，分段的「随机间隔时间」最小 1 秒以上 | AstrBot 每段先睡这么久，节奏被它盖住 | 扩展功能 → 分段回复，改成 0.3,0.8 这种 |

活人感那一块关着的，跟它打架的那项就不报（比如群聊节奏关了，主动回复就不算抢）。AstrBot 的默认配置查出来是 0 项冲突、2 项建议（@全体成员、群聊上下文没开）。键名和为什么打架都是读 AstrBot 4.29 的源码查的（`astrbot/core/config/default.py`、`waking_check`、`result_decorate`、`event_bus`、`group_chat_context`），单测会拿装好的 AstrBot 的默认配置把键名再对一遍。

## 免打扰时段（v0.5.0，默认不开）

配置 → 最上面「总开关 · 档位 · 免打扰」那组：

- 「免打扰时段」：一行一段，比如 `01:00-07:00`；可以跨半夜（`23:30-07:00`）、可以写几段。留空 = 不免打扰。
- 「免打扰按哪个时区」：默认北京时间（`Asia/Shanghai`）。北京时间、`UTC+8` 这种不用装 tzdata；`Europe/London` 这种名字在 Windows 上要装 tzdata，认不出就按北京时间算（日志会说）。留空 = 跟服务器的时间。
- 「免打扰时被 @ 也不回」：默认关。

这段时间里：

- 群聊节奏不接话、不挑着接（没 @ 的一律不接，接话打分也不跑）、冷场不试探、到点不说收尾话（悄悄回观望）；
- 群里没人找它、却要叫模型的（别的插件标了接话 / 插话 / 冒泡的、AstrBot 自带的主动回复）拦下；别的插件调 `ask()` 问能不能在群里主动说话，回「不行」；
- 被 @ / 引用 / 用唤醒词叫它的照回（「免打扰时被 @ 也不回」开着才不回；指令照常）。只叫它名字、没 @ 的不算 —— 那种平时也是群聊节奏打分决定接不接，免打扰时一律不接；想让「名字开头」的消息也算叫它，把名字加进 AstrBot 的「唤醒词」；
- 私聊不受影响。

面板总览、群聊节奏页写着「现在在免打扰（… 还有几分钟）」，今天拦下几次；`/活人感` 多一行免打扰；日志 `[免打扰]`、`[节奏] … 免打扰时段`。

## 装了同类插件会自动让路

加载时检查装了、启用了哪些同类插件。两个插件都在主动接话、都在合并连发的消息，会重复回、互相打断，所以按下表让路：

| 装了 | 让路的 | 为什么 |
|---|---|---|
| `group_chat_plus` / `SpectreCore` / `Heartflow` / `natural_followup` / `jiehua` | 群聊节奏、攒一攒 | 它们也在读空气、接话 |
| `angel_heart`（天使之心，v0.3.0） | 群聊节奏、攒一攒、省 token 的拦截（照样记账） | 它自己管接不接、自己有「能量」。它放行一条回复前会先登记「处理中」，消息发出去才收口；我们在调模型之前把它放行的那条拦下，它那边要等 300 秒兜底才恢复 |
| `reply_merge`（思维链式消息防抖，v0.3.0） | 攒一攒 | 它也在合并同一个人连发的几条 |
| `debounce`（消息防抖，v0.4.2） | 攒一攒 | 它跟攒一攒挂在同样两个钩子上判「说完没」 |
| 对话分段 Pro（v0.4.2） | 发消息（打字节奏 / 刹车） | 它前几段自己发、绕过 event.send，我们的打字节奏和刹车管不到 |
| Enhance Mode（群聊增强，v0.4.2） | 群聊节奏 | 它的主动回复开着时会和群聊节奏抢着回 |
| `qq_enhance`（QQ 能力增强，v0.3.0） | 攒一攒，只在它的「消息防抖」开着时（它默认开着） | 它的防抖也在等、在合并，还会取消正在生成的回复；两个叠在一起会多等一轮、互相打断。想用攒一攒：把它的「消息防抖」关掉（它的配置 → 消息防抖 → 启用消息防抖），或者在这里「强制开攒一攒」 |

面板的「让路情况」和日志都会写明因为装了谁、让了哪几块。

跟天使之心一起装（v0.4.3）：活人感拦下一轮（攒一攒、省 token、兜底不发）时，会替天使之心把它那一轮记成结束 —— 不然它要等 5 分钟才当超时，这期间那个群谁 @ 都不回。

私聊里不让路（v0.4.2）：读空气类、天使之心、Enhance Mode 只在群里干活，私聊里的攒一攒、省 token 照常；`reply_merge`、`qq_enhance`、`debounce` 私聊也管，照旧让。AstrNa 读过代码（v0.4.3）：它的 33 个开关里 32 个默认关，默认装着跟活人感不打架，所以不进让路名单；只有打开它的「解锁群聊并发回复（实验性）」时，同一个群几个人的回话会并行生成、它自己排着发 —— 跟攒一攒、打字节奏会互相干扰，这时候二选一：要么关掉它的群聊并发，要么把 `AstrNa` 填进「另外要让路的插件」。

- 想不让路：配置 → 兼容 → 「强制开攒一攒」/「强制开群聊节奏」/「强制开省 token 的拦截」，或关掉「自动让路」。
- 想让别的插件也触发让路：配置 → 兼容 → 「另外要让路的插件」，填目录名里的一段（至少 3 个字；群聊节奏和攒一攒让路）。

## 从旧三个插件换过来

第一次加载时自动做两件事（只读旧的，不删、不改旧目录）：

1. 把旧三个插件的存档（`plugin_data/astrbot_plugin_fatfish_{gather,rhythm,budget}/state.json`）搬进新插件的 `state.json`；
2. 把旧三个插件的配置（`config/astrbot_plugin_fatfish_{gather,rhythm,budget}_config.json`）里改过的项搬进对应分组（新插件里已经改过的不动）。

迁完以后在存档里打一个标记，不会再迁。迁移的结果在面板「总览 → 旧存档迁移」里看。换完确认没问题，再把旧三个插件从 `data/plugins` 里删掉（**不要两边一起开**，它们会同时在接话）。

## 配置

`_conf_schema.json` 分七组，WebUI 里每一项都有中文说明和提示：

- **总开关 · 档位 · 免打扰**：`alive.preset` 档位（最上面一项，见「新手先看：档位」）、`alive.enabled` 总开关（关了整个插件不做事）、免打扰时段 / 时区 / 免打扰时被 @ 也不回（v0.5.0，见「免打扰时段」）。
- **攒一攒**：私聊 / 群里攒不攒、基础等几秒、只有图多等几秒、问句只等几秒、最多等几秒、「稍等」最多等几秒、不攒的群、尾巴含糊多看一眼 / 问哪个模型 / 一轮最多问几次、他还在输入多等几秒（v0.3.0，默认开）、还排着没回他撤回了不回（v0.4.0，默认开）……
- **群聊节奏**：接话的窗口和分数线、最多连着接几轮、在线一阵的时长和挑着接的概率、冷场试探、收尾和冷却、「收尾句不接」「话题词没对上扣分」、「跟别人的话更像扣分」「开头叫别人扣分」（v0.2.0，默认开）、接话打分（v0.4.0：影子 / 生效 / 关，默认影子；过几分接、拿不准的范围、沉默加成、记录留几天）……
- **省 token**：价格、峰谷价、half / 形状 / 底线、各场合的次方、不限的 QQ 号、火力全开默认几小时、「有人找它就一定回」（v0.4.3，默认开：私聊、群里 @ / 引用 / 叫它名字（唤醒词）的不掷骰子，省 token 只省它自己想插嘴、接话、冒泡的那些）……
- **兜底**：拦报错、空回补救、补救超时、草稿外泄（v0.4.1，默认开）、去 AI 腔（默认关）、私聊回不上时说一声（v0.4.3，默认开：私聊里模型出错、补救也没要到时，换成一句系统提示，不让对方以为它不理人；同一个人 30 分钟最多一次，群里不发，那句话能改）。
- **发消息**（v0.2.0）：打字节奏（默认关）、每秒几个字、一条最多等几秒、打字刹车（默认关）、群里又来几句就不往下发、群里引用哪条（默认「跟着 AstrBot 的引用回复」）、撤回 / 算了剩下的不发（v0.4.0，默认开）。下面单独说。
- **兼容**：自动让路、强制开（攒一攒 / 群聊节奏 / 省 token 的拦截）、另外要让路的插件。

每个模块都有自己的 `enable`：关掉一个，别的照常。

群聊节奏、省 token、攒一攒里有 12 项的说明后面标着「档位管」（v0.5.0）：最上面的「档位」不是「自定义」时，这几项按档位走、你填的不看（见上面「新手先看：档位」）。

### 攒一攒：尾巴含糊才问、他还在输入（v0.3.0）

规则等完了（「问句只等 1.2 秒、普通 2 秒……」那套），回之前再看一眼：

- **他还在输入**（只有私聊）：QQ 端说他最近 6 秒还在「正在输入」，就接着等，最多多等 8 秒。要 QQ 端发「对方正在输入」的通知（NapCat 会发）；收不到就跟以前一样。
- **尾巴含糊**：最后一句的结尾是「那个 / 然后 / 还有 / 就是 / 而且 / 但是 / 所以 / 比如 / 首先 / 第一」、逗号、顿号、冒号、省略号，或者在列举（有「1.」没有「2.」），多半话没说完。这时问一次判断模型「他说完了吗」：
  - 只给它他这一串话和前面 3 行聊天，不带人设；最多等 4 秒，超时、出错都当成说完了。
  - 模型回「等 N」就再等 N 秒（3~12）；这期间他又发了，就整个重新算。
  - 一轮最多问 2 次。问的用量记进省 token。
  - 用哪个模型：「尾巴含糊：问哪个模型」，留空就跟群聊节奏的判断模型一样，那个也空就用对话模型。选个便宜、快、不开思考的。
  - 不想调模型：关掉「尾巴含糊：问一次判断模型」，就固定多等 4 秒。

### 撤回 / 算了：还没发的就不发了（v0.4.0，默认开）

两个地方，各一个开关：

- **攒一攒里还排着**（攒一攒 → 「还排着没回、他撤回了：那条不回」）：他发完一条、机器人还在等他说完的时候，他把那条撤回了 → 那条不并进来、不回。
  - 排着的只有那一条 → 这一轮不回（马上结束，不用等满）。
  - 在等的那条撤回了、他前面还有几条 → 只回前面的（模型收到的没有撤回的那句）。
  - 群里 @ 它的那条撤回了、剩下的只是没 @ 的随口话 → 不回。
  - 撤回通知比消息先到（图还在下载这种）也认得出：记 10 分钟。
- **正在分段发**（发消息 → 「撤回 / 算了：剩下的不发」）：AstrBot 开着「分段回复」时，每发一段之前看一眼（第一段也看）——他把机器人在回的那句撤回了，或者又明确说了「算了 / 不用了 / 别说了 / 不用回了 / 当我没说 / 发错了」这类 → 这段和后面没发的都不发了，**第一段已经发出去了也一样**。
  - 只认开头就是这些的：「我算了一下」「不用了解」不算；他 @ 别人 / 引用别人说的不算；别人说的不算。
  - 只是又补了一句（不是叫停）不归这里，归下面的打字刹车（默认关）。两个都开着时，撤回 / 算了算「叫停」、不算刹车。
  - 对话记录：发了几段只留几段；一段都没发就叫停了 → 这一轮（他那句 + 没发的回话）都不进对话记录（AstrBot 自己遇到空回也是两句都不存）。
  - 没开「分段回复」：整段是一条，模型还在想的时候他撤回了 / 叫停了 → 这条不发。
- 面板总览「撤回 / 算了：叫停几轮（没发几段）」、攒一攒「他撤回了：少并几条 / 不回几轮」；日志 `[叫停]`、`[攒一攒] … 撤回`。
- 要 QQ 端发撤回通知（NapCat 会发 `group_recall` / `friend_recall`）。

### 接话打分：8 条理由（v0.4.0，默认影子）

群里没点名它的消息，原来是按几个信号加减分（它刚回的人 +2、说「你」+1.5、在问 +1……）决定接不接。v0.4.0 加了一套按 **Inner Thoughts**（Liu 等，CHI 2025，arXiv 2501.00383）的 8 条内在动机打分，给每次接 / 不接一个看得懂的理由：

| 条 | 看什么 |
|---|---|
| 相关 | 叫了它的名字、它刚回的就是他、接了它的词、在说它刚才的话；开头叫的是别人、跟别人的话更像 → 低 |
| 信息缺口 | 在问（冲它问的更高）、在求助；只是应一声、收尾句 → 0 |
| 预期影响 | 话越有内容越高，求助 / 问看法更高；只是应一声、只发了图 → 低 |
| 紧迫 | 紧跟着它说的、冲它问的、「急 / 在吗」 |
| 连贯 | 它刚回的就是他、它说完以后他第一个开口；中间有别人插了好几句、他在跟别人一来一回 → 低 |
| 原创 | 在复读、只是应一声、别人已经在聊这个 → 低 |
| 平衡 | 它最近说得多 → 低；他很少说话 → 高（照顾少说话的人）；已经连着接了他好几轮 → 低 |
| 节奏 | 群里刷得快 → 低；在线聊着、冷了一阵有人开口 → 高一点；它刚说完、他又不是在回它 → 低 |

- 每条 0~5 分，取平均，再乘**沉默加成**：它在这个群上次说话以后，群里每过一句 × 1.02（论文里的数），最多 × 1.3 —— 沉默越久越想说。过线（默认 3.2）接。
- **全用规则算，不调模型，一次多花 0 个 token**。论文是先让模型想一句「想说的话」再打分，那要每条多一次完整调用；这里只给「这时候开口」打分。
- 只在原来就会判断的范围里打：它刚说完话的接话窗口里（默认 150 秒）、或者在线聊着的时候。
- 三个模式（群聊节奏 → 「接话打分」）：
  - **影子**（默认）：接不接照旧按原来的规则，打分只记下来。面板「群聊节奏 → 接话打分」看最近 40 次：8 条的分、理由、打分怎么说、原来的规则接没接。
  - **生效**：换成按分数决定。硬规矩照旧：收尾句不接、同一个人不 @ 最多接几轮、在线时挑着接的间隔和次数、正在回别人时不挑着接；省 token 照旧在叫模型之前掷骰子。线上下 0.4 分以内算拿不准：在接它的话那种问一下判断模型（跟「接话：拿不准时让模型看一眼」同一个开关、同一个模型、同一段问法），挑着接那种按线定。
  - **关**：不算。
- **事后的证据**（自动记）：没接、他 90 秒内又 @ 了它 → 「多半漏接」；接了、模型自己回了 `[[不说]]` → 「多半不该插」。都按打分当时怎么说分开数。
- 每次打分写进 `data/plugin_data/astrbot_plugin_fatfish_alive/inner/日期.jsonl`（一行一次：时间、群、谁、前 60 个字、8 条分、总分、打分怎么说、实际接没接、事后的证据），留 14 天（「记录留几天」，0 = 不写）。只在你电脑上。

**影子跑几天以后怎么看要不要生效**（面板上的数 + 记录文件）：

1. **打分会多接**（打分说接、原来没接）：翻这几条的原文，标「该接 / 不该接」。不该接的比例就是生效以后多出来的误插。
2. **打分会少接**（原来接了、打分说不接）：其中「模型选了不说」的是原来就不该插、打分躲开了（好）；剩下的翻原文看是不是漏了。
3. **没接、后来他又 @ 了它**：按打分当时怎么说分开看 —— 打分也说不接的，是生效以后会漏的；打分说接的，是原来的规则漏了、打分能补上的。
4. 一个参考的生效条件：跑满 3 天、打过 200 次以上分；「打分也不接、后来又 @ 它」不比原来多；「打分会多接」里标出来不该接的不到三成。不满足就先调「过几分接」（高一点 = 少接）再看。

### 发消息：打字节奏 / 打字刹车 / 引用（v0.2.0）

这一块不自己切段、不自己发，管的是 AstrBot 发每一段之前的那一下，所以要跟 AstrBot 自己的两个设置（配置 → 平台设置）一起看：

- **分段回复**（AstrBot 的 `segmented_reply`）：负责把一段话按句子切开、每段前面睡一个「分段间隔」。
  - 打字节奏开着：每段该「打」多久由本插件算（字数 ÷ 每秒几个字，第一段先读完对方的话、扣掉模型已经想过的时间）；AstrBot 已经睡过的分段间隔算进去，只补差的，**不会两边都等**。建议把 AstrBot 的分段间隔调小（比如 `0.3,0.8`），节奏就主要由本插件定。
  - 没开分段回复：整段当一条发，打字节奏按整段字数算（最多等「一条最多等几秒」）；打字刹车没有可刹的（只有一条）。
  - 流式输出不经过这一步，打字节奏 / 刹车 / 叫停 / 引用都不管。
- **打字刹车**：她分段发、还没发完，对方又说话了 → 后面没发的不发了，下一轮一起回（他撤回了她在回的那句；他说「算了 / 不用了」；他又说了一句正经的、会再回他的；群里她打字的时候又来了好几句）。第一段一定发；「嗯 / 哈哈 / 好的」不算。没发的不会记进对话记录。
- **引用回复**（AstrBot 的 `reply_with_quote`）：AstrBot 开着时会引用「触发这一轮的那条」——攒一攒并了几条时常是最后补的一句，私聊、一来一回也挂。本插件默认（`smart`）在你开了它的时候换成「找她的那一条」，该不挂的去掉；规则：只引用 @ 她 / 叫她 / 回复她 / 接着跟她聊的那条；好几个人在等她回 → 她这句提到谁就引用谁；她自己插话不引用；只有一个人、中间没别人说话不引用；私聊不引用。想 AstrBot 没开也这样挂：选「插件自己定」；想完全照 AstrBot：选「不管」。

## 指令（只有 AstrBot 管理员能用）

- `/活人感`：各模块现在开没开、有没有在让路（v0.3.0 写明因为装了谁、让了哪几块）、今天的数（v0.2.0 多一行发消息：打字节奏 / 刹车 / 引用开没开、今天刹了几次车、换了几次引用）；v0.5.0 第一行写着现在的档位，多两行：免打扰、上次自检几项冲突几项建议。
- `/活人感 自检`（v0.5.0）：重新查一遍 AstrBot 自己的设置里跟活人感打架的，回话里每项写现在怎样、为什么、在哪改（也写进日志）。只读。
- `/省token`、`/省token 火力全开 [小时数|一直]`、`/省token 省着点`、`/省token 重新算`：跟原来的省 token 插件一样。

## 给别的插件用

跟原来的省 token 插件一样，三个公开方法还在（插件名换成 `astrbot_plugin_fatfish_alive`）：`record_usage(resp)`、`ask(kind, conv, uid, name, where)`、`full_on()`。别的插件在 `event` 上写 `event.set_extra("fatfish_kind", "follow" | "chat" | "extra")`，省 token 就按这个场合算。群聊节奏会去问认 AI 插件（`astrbot_plugin_fatfish_aiguard`）这个群里谁是别家的 AI，没装就读它的 `state.json`。

## 已知限制

- 「模型回完什么都没有」在 AstrBot 4.29.3 里是被当成报错发出来的（`EmptyModelOutputError`），兜底会拦下并补调一次；「只有 `<think>`」会变成一条空消息，兜底在模型回完时补调并替它发出去。这两处都是照 4.29.3 的行为做的，升级 AstrBot 以后行为可能变。
- 框架里有些报错是直接 `event.send` 发出去的，不经过「发送前」那一步，拦不住（目前认得的主要报错都经过）。
- 兜底的补救会多叫一次模型（很轻：人设 + 这条消息 + 群里最近几句），计入省 token 的账。
- 草稿外泄只认开头的英文草稿（标签 + 英文为主、至少 4 个英文词）；中文写的草稿、夹在中间或结尾的认不出来。对话记录里那条回话也去掉草稿（整条都是草稿、补调到了 → 记成补的那句；没发 → 这一轮不存），靠的是 AstrBot 内部正在跑的那一轮（跟「叫停」一样），对不上就不改。
- 打字刹车后「对话记录里只留发出去的那段」用的是 AstrBot 内部正在跑的那一轮（4.29 里 `pipeline/process_stage/follow_up` 登记的）；以后 AstrBot 改了对不上就不改（日志会写），别的照常。
- 打字节奏开着时，这一轮「打字」的时间里 AstrBot 的会话锁还拿着：同一个会话的下一条要等她打完（跟真人一样）；刹车会让她提前停下来。
- 「他还在输入」只认 QQ 端发来的「对方正在输入」通知（NapCat 的 `notify / input_status`）；停止输入时 QQ 发的是什么没核实过，所以按「6 秒内收到过就算还在输入」算。群里没有这个通知。
- 防伪造只改「他说的话」和 AstrBot 群聊上下文里的「[群聊节奏]」；更早的对话记录里已经存下的不改。
- 撤回 / 算了（v0.4.0）：撤回只认 QQ 端发来的撤回通知；「算了」那几个词是写死的、只认开头；他已经说完、机器人整段都发出去了才撤回的，不管（对话记录里还是原样）。一段都没发就叫停时「这一轮不进对话记录」靠的是 AstrBot 内部正在跑的那一轮（跟打字刹车一样），对不上就不改（日志会写）。
- 接话打分（v0.4.0）是规则近似：没有像论文那样先生成「想说的话」再评，所以「预期影响」「原创」只能看对方这句话本身；分数线 3.2、每条怎么加减是按测试里的例子定的，没有拿真实群聊标过 —— 这就是默认影子的原因。
- 档位（v0.5.0）的三套数是按「话多不多」的道理和测试里的例子定的，没有拿真实群聊调过；嫌哪档不合适，选「自定义」再一项项调。档位只管那 12 项，别的细项（接话窗口、扣分、引用、打字节奏…）三个档位都一样。
- 启动自检（v0.5.0）只看 AstrBot 自己的设置，不看别的插件的；是插件加载时查的，之后改了 AstrBot 的设置要点面板「重新检查」或发「/活人感 自检」。键名和行为是照 AstrBot 4.29.4 的源码对的，AstrBot 以后改了可能看不准（单测会拿装好的 AstrBot 默认配置对键名）。「会打架」是读代码推出来的，「主动回复」那条在 e2e 里真开过，别的几条没在真群里复现过。
- 免打扰时段（v0.5.0）管的是活人感自己的（群聊节奏、要叫模型之前那一步、给别的插件的 `ask()`）：别的插件不叫模型、直接发的消息（比如定时推送），或者不问 `ask()` 就自己主动说话的，管不到。时段按分钟算，正在回的那一轮不会因为进了免打扰被打断。
